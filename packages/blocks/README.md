# @ng-email/blocks (private)

The source of the copy-paste email **blocks** and **templates** that appear on the ng-email website and that `ng-email add` installs. This package is not published; developers get the files with:

```bash
npx ng-email add header-centered order-summary welcome
```

```bash
npx ng-email add --list
```

## What's here

* `src/blocks/*.ts`: 21 blocks (sections you drop into your own email): headers, hero, buttons, avatars, features, lists, stats, testimonials, pricing, ecommerce, articles, gallery, dividers, feedback, footers.
* `src/templates/*.ts`: 5 complete emails: welcome, receipt, password reset, sign-in code, team invite.
* `src/registry.ts`: the catalog (name, title, category, selector) that drives everything.
* `assets/`: placeholder images (PNG, generated by `scripts/make-assets.mjs`, published under the website's `/static/`).

All designs, copy and images are original. The fictional brand is "Acme".

## Rules for a block

1. **One self-contained file.** Import only from `@angular/core`, `@angular/common` and `@ng-email/components`, because the file is copied into other people's projects. Put helper types and constants (like `FONT`) in the same file. A test enforces this.
2. **Element selector with a hyphen** (`header-centered`). The renderer unwraps the host, so only the block's own markup reaches the email.
3. **Every input has a sample default.** Previews and `ng-email export` render with no inputs.
4. **Email-safe layout:** tables via `ngeSection`, `ngeRow` and `ngeColumn`, inline styles via `ngeStyle`, no `styles` and no `[style.x]`. Blocks are sections designed for a 600px container. Templates are full documents (`html[ngeHtml]`).
5. **Images** reference `https://yshashi.github.io/ng-email/static/<file>`, and the file must exist in `assets/`. A test checks this.

## Scripts

| Command | |
|---|---|
| `npm run build -w @ng-email/blocks` | compile all blocks with `ng-email`'s own pipeline and write `dist/r/index.json` + `dist/r/<name>.json` (source + rendered preview HTML and text) and `dist/static/` |
| `node scripts/generate-registry.mjs --asset-base http://127.0.0.1:4320/assets/` | same, with preview images pointing at a local server (source files keep the public URL) |
| `node scripts/contact-sheet.mjs` | `dist/contact-sheet.html` and `dist/preview/<name>.html` for reviewing designs |
| `node scripts/make-assets.mjs` | regenerate the placeholder PNGs (deterministic) |

## Registry format (`registryVersion: 1`)

`dist/r/<name>.json`:

```jsonc
{
  "registryVersion": 1,
  "name": "header-centered",       // ng-email add <name>
  "title": "Header with centered menu",
  "description": "…",
  "category": "Headers",
  "kind": "block",                 // or "template"
  "className": "HeaderCentered",
  "selector": "header-centered",
  "file": "blocks/header-centered.ts",
  "dependencies": ["@ng-email/components"],
  "files": [{ "path": "header-centered.ts", "content": "…source…" }],
  "preview": { "html": "<!DOCTYPE …>", "text": "…" }
}
```

`ng-email add` only writes `files[].path` values that are plain `*.ts` file names. Anything with a directory or `..` is refused.
